# 内置音乐采集

从 1.2.0 起，默认的音乐采集直接在挂件进程内运行，不再启动 MusicFetcher，不监听旧的 12580／12581 采集端口，也不需要为音乐采集安装 .NET。

## 怎样取得歌曲

挂件通过 Windows 系统媒体会话（SMTC）读取播放器公开的标题、歌手、封面、播放状态和时间线。后台线程处理系统事件，低频查询作为兜底；播放按钮也通过系统会话向播放器发送命令。

在设置中选择“自动”，会跟随系统当前媒体来源；选择具体程序后，只接受对应的精确来源，不会在失败时悄悄改成其他播放器。

QQ 音乐和网易云客户端需要开启自己的系统媒体控制功能。浏览器或其他播放器能否读取，同样取决于它是否向 Windows 公开媒体会话。这不是账号登录接口，不读取 Cookie、密码或私有数据库。

## 频谱怎样采集

频谱使用进程内 WASAPI 回环采集与 DSP。自动模式可以采集系统音频；指定程序时，只采集能够精确匹配的目标进程。

应用进程 loopback 需要 Windows Build 20348 或更新版本，且实际设备和系统接口必须可用。不支持或匹配失败时显示不可用，不扩大到整机音频。关闭频谱会释放相应采集；暂停时停止音频分析，设备或来源变化时串行重建。

FPS 监视器仍使用随附的 PresentMon。它是图形帧率采集工具，不是音乐采集插件，不因为移除 MusicFetcher 而被删除。

## 系统与播放器边界

- 主程序要求 Windows 10 2004（Build 19041）或更新版本的 x64 系统；进程级频谱有上述更高要求。
- 播放器没有公开媒体会话时，无法凭空补出歌名或封面；有媒体会话也不代表所有字段都存在。
- 已在本机验证 QQ 和网易云的歌曲、封面及指定进程频谱。网易云测试版本能上报歌曲，却没有提供有效总时长；这种情况下不伪造播放进度，依赖时间线的歌词定位和下一首预告也可能不可用。
- 独占输出、受保护音频、虚拟声卡、蓝牙或设备热切换仍可能受到系统与驱动限制，不保证全部硬件组合均通过实测。
- 本次没有完成优化后整机 CPU／GPU／内存的同条件对照，不据局部 DSP 测试宣称整体占用下降比例。

## 源码构建

默认构建只需要 Flutter Windows 开发环境和 Visual Studio C++ 桌面开发组件，不需要先发布 MusicFetcher。运行 `flutter pub get`，然后运行 `flutter build windows --release`。

旧采集后端源码保留为显式开发回退，不进入默认发行运行目录。只有同时显式设置 Dart `LEGACY_MEDIA_BACKEND=true` 与 CMake `MD3_BUNDLE_LEGACY_FETCHER=ON` 才会部署使用；原生失败不会静默开启它。该开发模式不属于 1.2.0 发行验证范围。
