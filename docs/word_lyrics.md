# 逐字歌词与消散效果

1.1.0 增加基于真实时间轴的逐字歌词和可选消散效果。只有源数据包含有效的字／词级时间时才启用，不根据普通整句 LRC 平均猜测每个字的时长。

## 使用

在设置上方选择“歌词”，开启“显示歌词”和“逐字高亮”，再选择歌词提供商。存在真实字／词／音节时间轴时按时间推进高亮；没有时间轴时显示普通整句歌词，不平均分配每个字的演唱时长。

三种句内样式：平滑扫色、柔和点亮、轻微抬升。它们独立于既有的整句进入／退出动画。也可开启“消散歌词”：每个字／词唱完后短暂停留，再按自身演唱时长柔化、上飘和消散；此时不叠加逐字扫色。暂停会冻结，回拖时按新位置恢复，系统减少动态效果使用原位淡出。

未唱部分明暗可调整；歌词时间微调范围为 -5.000～+5.000 秒，正值提前、负值延后，不影响播放进度、音频或下一首预告。双击滑块上方的数值，可精确输入至 0.001 秒；内部保存格式仍为毫秒，旧设置无需迁移。滑块沿用现有 MD3 控件，并带重置。

高亮样式和未唱部分明暗只在当前歌曲提供逐字信息、且逐字高亮已开启时显示。没有逐字数据并不是“歌词不存在”，不会触发无歌词自动隐藏。

## 来源与格式

- QQ 音乐：公开歌词接口返回的 QRC 在后台 isolate 中通过兼容解码器解码，优先采用真实时间；普通 LRC 与既有 LRCLIB 回退保留。新增 qrc_codec.dll 是小型原生格式解码依赖，不是分层模型，也不依赖独显、核显、NPU或 .NET。
- 网易云：尝试公开新版歌词响应中的 YRC，异常／没有逐字资源时保留 LRC，原有 LRCLIB 回退继续工作。不同歌曲的资源覆盖率不同，不承诺每首歌都能获得逐字歌词。
- 本地：在既有本地歌词目录放置 `.ttml`、`.yrc`、明文 `.qrc`、`.alrc` 或 `.lrc`。使用“歌手 - 歌名.扩展名”或“歌名.扩展名”；精确匹配时先找逐字格式。
- TTML 首版支持音乐歌词常用的绝对时间戳段落／span，不是完整 TTML 字幕引擎；暂不单独排版合唱／对唱声部、音译、翻译或复杂相对时间容器。
- 增强 LRC 首版支持尖括号时间标记，最后一个片段需要明确结束标记；缺少结束时间或有无效片段时安全退为整句，不制造时长。加密本地 QRC、KRC、通用字幕格式不在本轮本地导入范围。

所有在线歌词请求继续直连，不使用系统代理，不读取登录 Cookie、账号凭据或播放器进程内存。平台访问限制与源内容可用性依然可能导致获取失败。

## 缓存与稳定性

磁盘缓存升级为包含行／字起止时间的新结构，旧版逐行缓存仍可读取。旧缓存先显示，后台尝试一次时间轴升级，不先换成加载指示；网络失败保留旧歌词并记录已尝试，避免重复播放时每次请求。缓存仍使用原有磁盘上限与逐出规则，重启后保留。当前提供的是全局歌词偏移，尚未增加逐曲偏移。

音频时间是高亮的时钟，缓动不改变歌词与音频的同步速度。只在歌词边界内重绘，整句排版与选区提前缓存；暂停、不可见或当前行结束时停止连续 tick。较大文本解析和 QRC 解码移到后台 isolate。减少动态效果时关闭抬升，保留表达播放进度的扫色。

网络响应、解码缓冲与解压结果有大小上限；解析器检查词时间、文本拼接和片段数量，拒绝外部 XML 声明。解析失败时保留普通歌词路径。

### 查询与缓存改进（2026-10-15）

- QQ 在第一个匹配版本没有歌词时，再尝试一个通过歌名、歌手和时长检查的候选；仍优先逐字歌词，不用随意放宽匹配来提高表面命中率。
- 网易云逐字接口有独立的阶段预算；为空、格式损坏或失败时继续尝试普通歌词，之后保留 LRCLIB 回退。
- LRCLIB 精确接口失败或超时不再中断搜索；单次在线查询有总预算，旧歌曲的慢响应不再占住整条查询队列。保留请求启动间隔及服务端限流等待。
- 缓存命中的访问时间合并写入索引；歌词／封面内容仍以临时文件和原子替换提交，退出时刷新索引。较大载荷的校验以及较大的逐字缓存解析移到后台 isolate。
- 在“外观 → 缓存与存储 → 缓存位置”可更换文件夹或恢复默认位置。程序在所选目录下建立专用子目录，复制受管理的缓存，保留原位置副本；切换失败会恢复原位置。不会移动本地 LRC 文件、歌单或无关文件。启动时自定义磁盘暂时不可用会回到默认缓存位置，不阻止程序打开。

## 验证边界

已做公开 QQ 歌曲的搜索→QRC 获取→本机 Release 解码→逐字文档端到端验证（63 行、602 个带时间片段）。公开网易云 YRC 样本解析出 28 行、245 个片段；同一首 QQ 测试歌曲在网易云链路中回退为 LRCLIB 逐行歌词，说明来源并不具有相同覆盖率。

逐字绘制测试连续推进 40 帧，未触发父组件重建或歌词重新排版；这不是整机 CPU/GPU 降幅或 120/144 FPS 的实机保证。真实播放器、不同 DPI、不同刷新率的人工验收仍需单独进行。
